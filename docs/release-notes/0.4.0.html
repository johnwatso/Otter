Otter 0.4.0

Version 0.4.0 · Build 2026082816

Otter now follows how you actually want each share treated, tidies up the duplicate server entries macOS leaves in Finder, and stops overlooking the passwords already saved in your Keychain.

🔢 Connection modes

Each share states what it is for, and Otter’s mounting and reporting follow from that.

  • Choose Keep Connected, Adaptive, Manual, or Connect Once for every share.
  • A mode that promises availability reports an unexpected outage; a manual share stays quiet about simply not being mounted.
  • Connecting a share on demand no longer rewrites the long-term preference you chose for it.

🧹 Duplicate connections

One server, one entry — even when macOS knows it by several names.

  • Finder lists a server twice when a share is mounted through an alias of its name, such as “nas.local” rather than the “nas” it is browsed under. Otter reconnects the share through the browsed name so the pair collapses back into one.
  • Confirms both names lead to the same machine before changing anything, carries the saved password across, and puts the share back exactly as it was if the new address does not work.
  • Unmounts redundant copies of a share that is already mounted, keeping the one your share is configured to use. Busy volumes are never forced.
  • Recognises a share mounted under any name its server answers to, instead of reporting that macOS mounted a volume Otter could not find.
  • Turn the whole behaviour off under Advanced › Monitoring.

🔑 Keychain

Saved connections and stored passwords are found where macOS actually puts them.

  • Saved connections now appear when adding a share. macOS records the default SMB port as zero, and Otter had been discarding every credential that used it.
  • Finds a saved password under any spelling of a server’s name. Connecting through Finder files it under the Bonjour service name, and Keychain matches a server exactly, capitalisation included.
  • Share details and the Connection Doctor no longer report missing credentials for a server whose password is saved perfectly well.

🔄 Reconnection

A share that was working a moment ago is treated differently from one that was already away.

  • Retries an unexpected disconnect on a faster schedule, which suits a NAS that reboots briefly.
  • Learns several fallback addresses per share and tries them in your preferred IPv4 or IPv6 order.

⬇️ Updates

Decide when an update that has already downloaded is allowed to install.

  • Install as soon as it is downloaded, once Otter is idle, or at a set hour of the day.
  • An install waits rather than interrupting a mount or unmount that is partway through.
