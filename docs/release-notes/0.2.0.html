Tighten new-share detection edges

Coalesce the announcement across debounced volume events. A mount
immediately followed by an unmount elsewhere took the last event's
announcing flag, which silently recorded the new share as known and
never offered it.

Deliver the workspace notifications on the posting thread instead of
through OperationQueue, since the handler only hops to the main actor
to schedule the scan.

Wait for the shares window to report that it appeared before presenting
the prefilled editor, replacing a fixed 250ms delay that guessed at how
long the window takes to open.

Drop the time-sensitive interruption level: the app ships without the
entitlement for it, so the system downgrades it anyway. The notification
already persists through the .list presentation option and having no
expiry.
